## What to include in future entries

<Expandable title="Writing guidelines for future releases" default-open="false">

- Keep each entry focused on the changes users will notice.
- Use the same structure every time so readers can scan quickly.
- Separate new features from bug fixes and upgrade notes.
- Avoid internal jargon unless your audience already knows it.
- Include dates and version numbers for every release.

</Expandable>

<Expandable title="Recommended release checklist" default-open="false">

1. Confirm the version number and release date.
2. Review user-facing changes for accuracy.
3. Verify links, headings, and code examples.
4. Check for spelling, formatting, and accessibility issues.
5. Publish the update and archive older notes when needed.

</Expandable>
